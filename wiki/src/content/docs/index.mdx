`pi-delegation-policy` is a local Pi extension that guides the main agent on when delegation is worth
it and which exact models to use for Small, Medium, Large, and the optional Visual Design and Advisor
roles. It adds guidance to the system prompt and nothing else: it does not route, supervise, or
collect delegated work, and it never changes Pi's main model, thinking level, or tool permissions.

What it configures:

- **Intensity** — `off`, `normal`, `aggressive`, or `orchestrator`, set globally or per branch.
- **Roles** — an exact `provider/model` reference or an explicit `disabled` for each ordinary role,
  plus the optional Visual Design and Advisor roles.
- **Thinking** — an optional fixed level or inclusive range per role, or no policy so the main agent
  chooses the level for each launch.
- **ContextShunt** — a separate opt-in layer that bounds recognized oversized context without
  launching a worker.

:::caution
The extension injects guidance only while an active configuration is valid. It cannot guarantee that
another system follows a configured role or thinking choice, and ContextShunt is off by default, not a
sandbox, and not an automatic worker bridge.
:::

## Start here

Version **0.17.0** requires Pi `0.87.1` or later (`>=0.87.1`). Version `0.14.1` supports Pi `0.84.3` or later (`>=0.84.3`).

<Steps>

1. Install `pi-delegation-policy` and reload Pi.
2. Open `/delegate` and give Small, Medium, and Large an explicit decision each: an exact
   authenticated model, or **Disable for this session**. Keep at least one enabled. Visual Design and
   Advisor are optional.
3. Choose an intensity, choose **Apply changes**, then confirm `/delegate status` reports `D:NORM`,
   `D:AGG`, or `D:ORCH`.

</Steps>

Optional next steps: set a per-role thinking policy, enable the Advisor with `/delegate advisor on`,
or turn on ContextShunt with `/delegate context observe`.

## Availability

Independent Advisor mode and the companion file that stores it are available from version `0.17.0`. A configuration saved without an explicit Advisor mode keeps the previous
behavior: Advisor is consulted only while delegation is active. Selecting `on` is what enables
consultation with delegation off.
