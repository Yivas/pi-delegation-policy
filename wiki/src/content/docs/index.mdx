`pi-delegation-policy` is a local Pi extension for delegation intensity and exact references for
Small, Medium, Large, and optional Visual Design. It guides the main agent; it never runs or routes delegated work. Its optional ContextShunt protects recognized oversized context without launching a worker.

:::caution
The extension adds guidance only when an active configuration is valid. ContextShunt is off by default and is not a sandbox or an automatic worker bridge. Neither capability can guarantee that another system follows a configured role or thinking choice.
:::

## Start here

<Steps>

1. Install `pi-delegation-policy` and reload Pi.
2. Open `/delegate`, configure or explicitly disable each of Small, Medium, and Large, and leave at least one enabled. Visual Design is optional.
3. Select `normal`, `aggressive`, or `orchestrator`, choose **Apply changes**, then confirm `/delegate status` and `D:NORM`, `D:AGG`, or `D:ORCH`.

</Steps>

`orchestrator` delegates all transferable execution before it begins whenever an enabled capable role and authorized launcher are available, regardless of size, including small lookups, code reading, detailed planning, implementation, testing, writing, detailed review, and integration mechanics. Bootstrap is only mandatory instructions, tool discovery, and narrow assignment scope. Pending work is not taken over or duplicated: coordinate disjoint work, wait through the host, and consume results before dependent work or finalizing. The main agent retains critical decisions, coordination, safety, evidence evaluation, final acceptance, and concise synthesis—not personal execution of transferable review or integration. Direct work needs a briefly stated concrete exception: genuinely non-transferable work, no enabled capable role, a confirmed unavailable authorized launcher, or an explicit user or higher-priority requirement. Reinspect only concrete gaps, risks, or contradictions and delegate transferable fixes or rechecks; a final-review label, size, triviality, convenience, economics, transfer cost, or familiarity is not a bypass. Published `0.9.0` includes the stricter guidance; published `0.7.0` retains its original policy. Before downgrading to 0.6.0, set the global intensity and each active branch to `off`, `normal`, or `aggressive`; for `<=0.5.0`, also convert global defaults to schema 2 and replace ordinary `null` values with exact model references. `disabled` is distinct from `not configured`. The latter, an invalid enabled reference, or zero enabled ordinary roles produces `D:ERR` and injects no policy. Pi `0.84.3` is the explicitly checked baseline; the package peer range is `>=0.84.3`.
